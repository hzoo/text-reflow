# Text Reflow audit

Text Reflow's strongest idea is semantic continuity: the sentence stays put while the presentation changes. The highest-value work is to make that promise reliable across importing, navigation, reflow, and mobile fit. The app already has useful performance foundations: demand-driven animation, viewport culling, cached measurements, and DOM rendering on mobile. A rewrite would discard working machinery without resolving the main failures.

This review covers the Preact/TypeScript app, both renderers, document parsing, input, storage, interface copy, and project instructions. Sol 6.1 implemented the narrowly scoped correctness fixes below. Poster overflow was approved and integrated after the audit. Other design, copy, and segmentation changes remain proposals.

## Fifth pass

Importing a Markdown divider produced zero readable sentences. The previous build showed `1 / 0` on desktop and `1/1` in mobile Poster. Its engine could also publish sentence index zero after stepping or jumping in an empty scope.

The engine keeps focus absent when a scope is empty. Document selection and mobile startup use the same empty cursor, and both progress displays show zero of zero. Two regression tests failed on the previous code and passed after the fix. The production builds reproduced the counts in Chrome using a mocked URL import. The patched count stayed at zero through desktop navigation, a mobile Poster → Scroll → Poster round trip, and startup on an empty article with a stale saved position. Reopening readable text started at sentence 1 and advanced to sentence 2 in both shells. See `src/syntaxExploder/engine-sentences.ts`, `src/state/signals.ts`, and `src/lite/LitePoster.tsx`.

## Auto sizing and article positions

Auto fits the current Canvas scope on first use and when the viewport, scope, or layout inputs change. Dragging Size or using the size shortcuts switches to Manual. The saved range now matches the 10–128 px control. In Chrome, the same fixture stayed at 24 px on the old build's first Auto click. The patched build fitted to 36 px, refitted to 26 px on a smaller viewport, and kept a manual 109 px through a view switch and reload.

Reading positions are keyed to library article IDs. Switching articles, opening a cached share link, reloading, and handing off between views use the owning article's position. Two entries with identical source can hold different positions. The old unkeyed sentence number has no verifiable owner, so a legacy record with only that number opens at the start. A deleted or evicted article's position is removed.

## Poster overflow

Poster uses continuation pages when a unit would need a body size below 18 px. The footer advances through pages while the unit counter stays in place. Long unbroken text wraps at grapheme boundaries.

At 360 × 640, the baseline rendered the long paragraph at 12 px and clipped nine lines. The preview presented it at 18 px across four pages. Chrome verified that every page stayed inside the reading area and that the pages reproduced the full rendered passage in order. A separate fixture preserved all 120 characters of an oversized token. The integrated build fit the same sample across three pages in Safari on an iPhone 17 Pro simulator. Both arrows, disabled controls at the ends, and backward navigation across a paragraph boundary were verified.

## State machine inventory

The useful change is fewer owners of the same fact. A statechart library is unnecessary here. Keep independent preferences independent; do not turn every boolean into an enum.

| Machine and location | States and events | Invalid or drifting combinations; treatment |
| --- | --- | --- |
| History and storage — `state/library.ts` | Missing/invalid/blocked restore → empty; valid restore → MRU entries. Add, select, delete, and eviction change the ordered list. | Active ID is now derived. A failed write still looks like a saved entry; retain a persistence outcome if surfacing it. The 20-entry cap silently evicts old entries: decide whether this is disposable history or a durable library. |
| Active document and starter — `signals.ts:93,147,240` | Bundled fallback; starter pending; selected/imported entry; empty history. Starter success/failure, import, select, delete. | Replacement now commits related values together and rejects stale starter results. Longer term derive text/format from the active entry instead of writable copies. |
| Reading cursor and scope — `App.tsx:104,220`, `signals.ts:207`, `engine.ts:763` | No focus or a document-global sentence; full/paragraph presentation. Step, wrap, jump, restart, scope switch, document replacement. | Global sentence, local engine sentence, and current paragraph can disagree. Make `{documentId, sentenceIndex}` authoritative; derive scope-local coordinates. Highest-value refactor. |
| Import and paste confirmation — `state/library.ts`, `PasteToast.tsx`, `main.tsx` | Idle, proposed text/URL, reading file or loading URL, success, failure; confirm, dismiss, timeout, replace, retry, cancel. | One owner coordinates asynchronous file and URL imports. | Panel — `ControlPanel.tsx:30`, `LiteHUD.tsx` | Closed or open; remembered Style/History tab. Button, shortcut, backdrop, center tap, Escape. | Remembering the tab while closed is valid; leave those two simple values. LiteHUD duplicates controls and sits behind the panel/backdrop when open. |

## Performance priorities

The release build and passing tests establish correctness and packaging. Browser profiling and frame-time measurements remain pending.

| Order | Candidate | Measurement that would justify a change |
| --- | --- | --- |
| 1 | Remove repeated whole-document passes and allocations during width/font scrubbing (`engine.ts:481,559,1018`). | Fixed 25k- and 100k-word passages; input-to-paint p95 and long frames during a repeatable scrub. First distinguish measurement, layout, and drawing cost. |
| 2 | Make warming focus-aware and avoid scanning unrelated paragraphs (`engine.ts:329,402`). | Cold jump to the end, then steady sentence navigation. Check correct geometry and anchor stability as well as latency. |
| 3 | Build poster atoms once per unit, avoid duplicate resize fits, and bound the width cache (`poster-layout.ts:47,140`, `LitePoster.tsx:78`). | Page turns and rotation on a phone; fit duration, input-to-paint, and retained cache size across many articles. Do not shrink text or drop content to improve the number. |
| 4 | Defer canvas-only code from the mobile boot path (`main.tsx:3,8`). | Production mobile cold start, downloaded JS, and first readable paint. Current static imports include both rendering paths; split only if the end-to-end result warrants it. |

For comparisons, use production builds, the same documents and viewport, alternate at least five runs per side, and report median/range plus p95 interaction latency. Reject gains within run noise and count incorrect/failed outputs. Keep the current demand-driven frame scheduler and viewport-local steady-state work.

## Verification and next decision

The baseline had 199 passing tests, the first pass had 213, the second had 220, the third had 226, the fourth had 228, and the fifth had 230. The Auto and article-position follow-up passed 232 tests with two unchanged snapshots. Type checking and the production build passed. Chrome verification used mocked external fetches, scripted input, and actual reloads. The desktop wheel comparison used native wheel input in both builds. History scrolled in both. On the baseline, the header and footer each advanced the reader by two sentences. With the fix, the reader stayed on sentence 1 through both panel actions, then advanced to sentence 3 when the pointer moved over the canvas.

The highest-priority unresolved source-loss bug is false verse detection in ordinary prose. Language classification and segmentation need agreed semantics. Import recovery, mobile ingestion, and reading accessibility still need interface review. Profile scrubbing and mobile fitting after those correctness boundaries are reliable.
